# Concierge DEP0169 isolation — 2026-09-08

## Incident

Production `/api/concierge` emits Node DEP0169 (`url.parse()` legacy API) on cold start under Node 24. The warning reproduced on production deployment `dpl_75ttas3dBhjYjcwDSaRuNfy5SAxn` at merge SHA `2320528e15f676d3853724eda7bfb0d7bd8383db` after the optional conversation store had already migrated from deprecated `@vercel/postgres` to `@neondatabase/serverless`.

## Isolation evidence

- `/api/feedback` imports `_store.js` but did not create a new DEP0169 occurrence during the comparison request.
- `/api/insights` imports `_store.js` and `_auth.js` but did not create a new DEP0169 occurrence during the comparison request.
- Repository search found no direct application call to `url.parse()`, `url.resolve()`, `url.format()`, or `require("url")`.
- The concierge runtime uniquely loaded governed JSON assets from filesystem URLs derived from `import.meta.url` before experiment 3.

## Experiment 1 — concierge entry point

PR #89 removed the unnecessary `fileURLToPath()` conversion from `api/concierge.js` and passed `new URL(name, import.meta.url)` directly to `fs.readFileSync()`.

### Result: not the full root cause

Production deployment `dpl_9HgiqFpBQQU3zMccaoeJ3KjKN1gF` at merge SHA `700eca0ad7982cfbe7135ca72616b716de485b44` passed normal release gates and served `/api/concierge` successfully. Before the cold-start request, the 15-minute DEP0169 snapshot was count `1`, last `2026-09-07T20:54:40Z`, on the previous deployment. After the request, delayed aggregation advanced the group to count `2`, last `2026-09-07T21:02:57Z`, with `lastDeployment=dpl_9HgiqFpBQQU3zMccaoeJ3KjKN1gF`.

Therefore PR #89 was a valid API simplification but did not eliminate DEP0169.

## Experiment 2 — concierge-only knowledge asset tracer

PR #90 removed the remaining `fileURLToPath()` conversions from `api/_knowledge.js` while retaining direct `new URL(..., import.meta.url)` filesystem reads.

### Result: still reproduced

Production deployment `dpl_3nzByq6xwKzmwGYmN7iqDnkwR4go` at merge SHA `af617684ab60f10202f2ae90a57e32c98936188e` was live with publication allowed. Immediately before the controlled `/api/concierge` cold start, the 15-minute DEP0169 snapshot was count `2`, last `2026-09-07T21:02:57Z`, on the prior deployment. After the cold-start request, aggregation advanced the group to count `3`, last `2026-09-07T21:08:53Z`, with `lastDeployment=dpl_3nzByq6xwKzmwGYmN7iqDnkwR4go`.

Therefore merely removing `fileURLToPath()` was insufficient.

## Experiment 3 — static JSON modules, no runtime URL/path conversion

PR #91 replaced the concierge filesystem loader with Node 24 static JSON module imports and removed the `_knowledge.js` runtime asset tracer. The truth validator was strengthened to require static governed JSON imports and reject reintroduction of `import.meta.url` or `readFileSync()` runtime asset loading.

### Result: still reproduced

PR #91 exact-head CI, AIPS Upgrade Validation, SEO quality, Playwright real-browser smoke, and Vercel preview all passed. Production deployment `dpl_BxrKmMs9JiUWFrQWGCazi1Mo2r8X` at merge SHA `a9a4218d31a66ae410023853b2375b6fa066ff79` was READY and the live build identity matched that SHA with publication allowed.

Immediately before the controlled production `/api/concierge` cold start, the 15-minute DEP0169 group was count `2`, last `2026-09-07T21:08:53Z`, and still pointed to the prior PR #90 deployment. The cold-start GET returned HTTP 200 at `2026-09-07T21:16:01Z`; the runtime group immediately advanced to count `3`, last `2026-09-07T21:16:01Z`, with `lastDeployment=dpl_BxrKmMs9JiUWFrQWGCazi1Mo2r8X`.

Therefore the governed JSON filesystem/import-meta path was not the root cause either.

## Diagnostic 4 — first application import warning listener

PR #92 installed a temporary zero-dependency `process.on("warning")` listener in `api/_dep0169-trace.js` and imported it before all other concierge dependencies. It logs only bounded warning metadata and stack for code `DEP0169`; it does not read request, environment, credential, catalog, payment, or customer data.

### Result: warning occurs before application module evaluation

PR #92 exact-head CI, AIPS Upgrade Validation, SEO quality, Playwright smoke, and Vercel preview all passed. Production deployment `dpl_5GtprnxnDSDfvTyAewvyewk3S2YK` at merge SHA `1ad2da3695b5603ff736a0d7bdb91433c905e0cd` was READY, aliased to `aipremiumshop.com`, and its live build identity matched that exact SHA with publication allowed.

Immediately before the controlled cold start, the 15-minute DEP0169 group was count `2`, last `2026-09-07T21:16:01Z`, pointing to the prior deployment. A production GET `/api/concierge` returned HTTP 200 at `2026-09-07T21:22:29Z`. The runtime group advanced to count `3`, last `2026-09-07T21:22:29Z`, with `lastDeployment=dpl_5GtprnxnDSDfvTyAewvyewk3S2YK`.

Deployment-specific runtime-log search for `dep0169_trace` returned no records. Because the listener was the first application import but could not observe a warning that Vercel recorded for the same cold start, the warning is emitted before application module evaluation. This is strong evidence for a Vercel/serverless bootstrap, helper, bundled wrapper, or other pre-application runtime layer. Do not continue guessing inside concierge application source.

## Diagnostic 5 — process-start deprecation stack trace

Temporarily add `NODE_OPTIONS=--trace-deprecation` to the existing Vercel runtime `env` in `artifacts/aips-landing/vercel.json`. Node 24 documents `--trace-deprecation` as printing deprecation stacks and permits the flag through `NODE_OPTIONS`. Vercel documents `vercel.json.env` as environment variables passed to invoked functions.

This diagnostic does not suppress warnings, downgrade Node, change business logic, or read secrets. Its sole purpose is to make the pre-application DEP0169 warning include the caller stack before application code begins.

### Verification rule

Require normal exact-head CI, AIPS Upgrade Validation, SEO/Playwright, and Vercel preview before merge. After the exact production SHA is live, cold-start `/api/concierge` and inspect the deployment-specific warning/runtime error stack. The next code change must target the concrete caller or, if the stack is wholly Vercel/runtime-owned, document and escalate the platform-origin issue rather than patching unrelated app code.

## Rollback / continuation rule

Keep every falsified experiment recorded. The incident is unresolved until a production cold start stops advancing DEP0169 after delayed verification, or the warning is conclusively attributed to platform runtime code with stack evidence and an appropriate platform mitigation/escalation is recorded. Remove temporary diagnostics when attribution is complete.

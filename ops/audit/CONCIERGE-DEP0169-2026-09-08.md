# Concierge DEP0169 isolation — 2026-09-08

## Incident

Production `/api/concierge` emits Node DEP0169 (`url.parse()` legacy API) on cold start under Node 24. The warning reproduced on production deployment `dpl_75ttas3dBhjYjcwDSaRuNfy5SAxn` at merge SHA `2320528e15f676d3853724eda7bfb0d7bd8383db` after the optional conversation store had already migrated from deprecated `@vercel/postgres` to `@neondatabase/serverless`.

## Isolation evidence

- `/api/feedback` imports `_store.js` but did not create a new DEP0169 occurrence during the comparison request.
- `/api/insights` imports `_store.js` and `_auth.js` but did not create a new DEP0169 occurrence during the comparison request.
- Repository search found no direct application call to `url.parse()`, `url.resolve()`, `url.format()`, or `require("url")`.
- `api/concierge.js` was the remaining serverless entry point in this comparison that converted an adjacent WHATWG file URL with `fileURLToPath()` before reading JSON assets.

## Experiment

Remove the unnecessary `fileURLToPath()` conversion and pass `new URL(name, import.meta.url)` directly to `fs.readFileSync()`. Node's supported filesystem API accepts a WHATWG `file:` URL as the `path` argument.

This change is a controlled hypothesis, not proof of root cause. It must not be described as fixed until all normal release gates pass, the exact production SHA is live, `/api/concierge` is cold-started again, and the Vercel runtime-error timestamp/count does not advance for DEP0169.

## Rollback rule

If DEP0169 reproduces on the experiment deployment, revert or supersede this change and continue isolating the concierge-specific bundled graph. Do not downgrade Node merely to hide the warning.

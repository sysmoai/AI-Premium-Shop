## 2. Architecture decision (Phase B)

**Cloudflare Workers with static assets** (single Worker, Free plan),
deployed with `wrangler deploy` (Wrangler v4).

Why not Pages:
- Pages force-redirects directory URLs to a trailing slash (308). The site's
  sitemap and every prerendered canonical are slash-less
  (`https://aipremiumshop.com/products`), and the repo's own live-site monitor
  curls those exact routes without following redirects. Workers assets support
  `html_handling = "drop-trailing-slash"`, which serves the slash-less URLs
  directly — exact Vercel parity.

Configuration (`wrangler.toml`):
- `main = "worker/index.js"`
- `[assets]` directory `./artifacts/aips-landing/dist/public`,
  `binding = "ASSETS"`, `not_found_handling = "404-page"`,
  `html_handling = "drop-trailing-slash"`, `run_worker_first = ["/api/*"]`.

Routing (`worker/index.js`):
- `/api/concierge`, `/api/feedback`, `/api/insights` handled by the Workers
  ports in `functions/api/*`; all other requests go to `env.ASSETS.fetch`.

API ports:
- `functions/api/concierge.js` — identical logic to the Vercel original
  (`artifacts/aips-landing/api/concierge.js`); transport replaced with
  Request/Response + SSE ReadableStream; secrets from bindings
  (NVIDIA_API_KEY, ANTHROPIC_API_KEY, INSIGHTS_TOKEN); logging via
  `ctx.waitUntil(logTurn(...))` with `@neondatabase/serverless`.
- `feedback.js`, `insights.js` — same porting rules. Fail-closed behavior is
  preserved: no NVIDIA key → 503 + WhatsApp fallback; no INSIGHTS_TOKEN → 503;
  no DB → store no-op, feedback acknowledged.
- Governed runtime assets (`_policy.json`, `_catalog.json`) are generated by
  the build and copied into `functions/api/` by
  `scripts/prepare-cloudflare.mjs`. The concierge refuses to start if they
  are missing or drifted (module-level `assertRuntimeTruth`).

Build/deploy:
- `pnpm build:cloudflare` = governed `aips-landing` build + prepare step.
- `pnpm deploy:cloudflare` = `wrangler deploy`.
- `scripts/prepare-cloudflare.mjs` writes `dist/public/_redirects`
  (39 vercel.json redirects) and `dist/public/_headers` (CSP + cache rules
  from vercel.json, /api/* rule first). No SPA splat: genuine 404s serve the
  static `404.html` with status 404.

## 14. Global access forensics + transitional fix (2026-10-14)

Root cause of the remaining Vercel responses on customer networks:
**stale recursive resolver state, not authoritative misconfiguration.**

- Registry/registrar delegation is CORRECT (Squarespace → Cloudflare NS).
- The legacy Google/Squarespace authoritative zone (ns-cloud-d1..d4)
  continued serving the old Vercel records. Any resolver whose cached
  delegation still pointed there kept receiving Vercel answers (A TTL
  14400; delegation cache up to 48h). This produced the Android
  "deployment paused" result.
- Resolver evidence (2026-10-14):
  - 8.8.8.8: NS = Cloudflare (updated), A = Vercel (cached) → then FLUSHED
    via dns.google/cache → now Cloudflare.
  - 1.1.1.1: NS + A cached old → converges via TTL expiry (≤4h).
  - 9.9.9.9: Cloudflare ✓.
  - Local ISP router: cached old → converges via TTL expiry (≤4h).
- Transitional fix applied (Squarespace Domains DNS settings, legacy zone):
  - A @ 76.76.21.21 → **104.21.19.189** (Cloudflare edge).
  - CNAME www cname.vercel-dns.com → **aipremiumshop.com** (apex, which is
    now Cloudflare). Verified via direct queries to ns-cloud-d1: both
    apex and www now resolve to Cloudflare IPs.
  - Zoho MX/SPF/verification TXT and Vercel verification TXTs unchanged.
  - Effect: every network converges to Cloudflare as its cache expires —
    worst case ≈4h (A TTL), no 48h delegation wait for old-NS resolvers.
- Google Public DNS cache flushed for apex + www via the official tool.
